# Anomaly detector: float model against int8

Generated by `python -m anomaly_int8 run`. The log is `desk_room_log.csv`, with 6048 readings (6045 windows of four). Training uses normal windows only; the threshold uses normal validation windows; the test uses the last 15 % of the log.

The held-out test has injected faults (spikes, stuck readings, humidity jumps and dropouts), so these numbers are for the simulated faults I put in, not for faults I have seen on the real sensor yet.

| Model | Accuracy | Precision | Recall | False alarms | Threshold | Memory |
|---|---|---|---|---|---|---|
| Float32 (PyTorch weights) | 0.9680 | 0.830 | 0.650 | 0.0094 | 663.00 | 592 bytes |
| int8 (C integer routine) | 0.9680 | 0.830 | 0.650 | 0.0094 | 703 | 223 bytes |

Accuracy loss from quantization: +0.0000. Decisions agree on 99.56 % of test windows. The reconstructed outputs differ by 0.510 units on average (max 38); one unit is 0.1 C or 0.5 %RH.

## Recall by injected fault (test windows)

| Fault | Test windows | Float32 recall | int8 recall |
|---|---|---|---|
| spike | 12 | 100 % | 100 % |
| stuck | 21 | 0 % | 0 % |
| humidity jump | 15 | 100 % | 100 % |
| dropout | 12 | 100 % | 100 % |

A stuck sensor repeats its last reading for four samples, and each window is four readings, so a stuck window looks like a calm room to this model. Catching it needs a longer window or a check on variance, which I have not added.

The input layer uses one device unit per step (0.1 C for each temperature, 0.5 %RH for each humidity), so the zero point is 0. The last layer reuses the input scale and zero point, so the score is a plain integer sum.
